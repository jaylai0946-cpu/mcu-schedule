# 國企一甲課表 📅

銘傳大學國際企業學系跨境電商經營組一年級的個人課表 + 作業考試待辦。
一個人用，沒有登入、沒有後端、沒有雲端同步 —— 資料只存在你自己的瀏覽器裡。

- 手機優先，可以「加入主畫面」當成 App 用，離線也開得起來
- 打開就看到「接下來要幹嘛」，快到期的排最上面
- 課表可以改，改的時候會擋下衝堂
- 學校的開學日、考試週、放假日登記進去，會和個人待辦一起倒數
- 內建官方行事曆全文，可以放大縮小查看，重要日期一鍵加進自己的清單
- 可以把課程和待辦匯出成 `.ics`，丟進 Google 日曆或 iOS 行事曆

---

## 開發

需要 Node 22 以上。

```bash
pnpm install
pnpm dev
```

開發伺服器會在 <http://localhost:5173/mcu-schedule/>（注意路徑，`base` 設成 `/mcu-schedule/`）。

| 指令 | 做什麼 |
|---|---|
| `pnpm dev` | 開發伺服器 |
| `pnpm test` | 跑一次 Vitest |
| `pnpm test:watch` | 監看模式 |
| `pnpm typecheck` | 只跑 TypeScript 檢查 |
| `pnpm build` | 型別檢查 + 產生 `dist/` |
| `pnpm preview` | 預覽 build 出來的結果（要測 PWA 就用這個，`dev` 不會啟用 service worker） |

版本號在「設定 → 版本」看得到。**手機和電腦顯示的版本號不一樣，就是有一邊還沒更新**——
按「檢查更新」可以手動抓。

## 部署到 GitHub Pages 🚀

1. 在 GitHub 開一個名叫 **`mcu-schedule`** 的 repo（名字要一致，見下方注意事項）
2. 推上去：

   ```bash
   git remote add origin https://github.com/<你的帳號>/mcu-schedule.git
   git branch -M main
   git push -u origin main
   ```

3. 到 repo 的 **Settings → Pages**，把 **Source** 改成 **GitHub Actions**
4. 之後每次 push 到 `main`，`.github/workflows/deploy.yml` 會自動跑測試、build、發布

網址會是 `https://<你的帳號>.github.io/mcu-schedule/`。

> ⚠️ **repo 名字必須和 `vite.config.ts` 裡的 `BASE` 一致。**
> 改用別的名字的話，`BASE` 要一起改成 `/<新名字>/`，否則上線會是一片空白。

## 裝到手機 📱

1. 手機瀏覽器打開上面的網址
2. **iPhone**：Safari 下方分享鍵 → 加入主畫面
   **Android**：Chrome 右上選單 → 安裝應用程式／加到主畫面
3. 從主畫面的圖示開啟。裝好之後沒網路也打得開

## 提醒功能的實際能力 ⚠️

這部分請照實看待，不要以為設定好就一定會響：

- 通知**只有在 App 開著的時候**才會排程與觸發。關掉分頁就不會響
- 這個專案**沒有**背景推播（不接任何後端或第三方推播服務）。
  `Periodic Background Sync` 支援度很有限，偵測不到就直接降級，設定頁會明說
- **iOS 必須先「加入主畫面」**，從主畫面圖示開啟，才發得出通知。
  沒裝就開通知是不會有效果的，設定頁會偵測並提示

**所以真正靠得住的提醒方式是行事曆匯出。** 設定頁的「匯出到系統行事曆」把 `.ics`
下載下來，在手機上點開選「加入行事曆」，提醒交給系統行事曆處理。

## 行事曆與重要日期 🗓️

分成兩個分頁，各管一件事。

### 「行事曆」分頁：官方行事曆全文

把 **銘傳 115 學年行事曆中文定稿 v4（115.03.16 教育部核定、07.01 教務處更新）** 整份轉成資料
放進 App（`src/data/academicCalendar.ts`），兩個學期都有，離線也看得到。

- **可以放大縮小**（50%–200%），手機上預設 60% 先看到整週，兩指也能直接縮放
- 今天的日期會標成深色，週末欄位加底色
- 「從行事曆加入重要日期」可以把上面的事項一鍵加進自己的清單，類型會依標題自動猜

轉檔的日期全部驗算過：每一格的星期必須和它所在的欄位相符（63 週、440 個日期），
測試裡有這條，資料重新轉出時如果算錯會直接紅燈。

> 要更新成別的學年，重新從官方 docx 轉出 `src/data/academicCalendar.ts`，不要手改那個檔。

### 「重要日期」分頁：自己登記的可以登記學校的重要日期：開學日、期中考週、期末考週、國定假日、補課日。
支援**日期區間**（例如期中考週 11/09–11/13），登記後：

- 近 30 天內的會出現在首頁「接下來」，和個人待辦一起依日期排序
- 進行中的區間會固定排在最上面，標示「進行中」與還剩幾天
- 一起匯出到 `.ics`（全天事件；只有「考試」類型會提前一天提醒，放假不會）
- 可以一鍵把其中一個日期帶入「學期起訖」的開學日或最後上課日

### 為什麼是「轉檔內建」而不是「線上同步」

查過了，線上同步的兩條路都不通：

1. **銘傳 eForm 平台確實有 iCal 訂閱**
   （`webcal://eform.mcu.edu.tw/calendar-node-field-date/ical/YYYY-MM/calendar.ics`），
   但內容是**表單申請通知**而不是學期行事曆，而且混雜其他校區。更關鍵的是那個伺服器
   **沒有回 `Access-Control-Allow-Origin`**，瀏覽器的同源政策會直接擋掉，純前端抓不到。
   要繞過只能架代理伺服器，違反「不要後端」的前提。
   如果你想看這個通知，**直接在手機行事曆訂閱那個 webcal 網址**比放進 App 省事得多。
2. **真正的學期行事曆是經行政會議通過的 PDF**，沒有官方的機器可讀版本。

所以改成把官方 docx 轉成靜態資料內建進來。好處是離線可用、不依賴學校伺服器；
代價是**學校改了行事曆不會自動更新**，要重新轉檔。

## 行事曆匯出

- **匯出全部**：課程（每週重複到學期結束）＋ 待辦（單次事件，附提醒）＋ 學校行事曆（全天事件）
- **只匯出待辦與學校日期**：不想讓課表塞滿行事曆的話用這個
- 時區固定 `Asia/Taipei`，輸出合法的 `VTIMEZONE`
- 課程用 `RRULE:FREQ=WEEKLY;BYDAY=…;UNTIL=<學期最後一天>`，
  一段連續節次是一個事件（開始 = 第一節開始，結束 = 最後一節結束）
- 待辦帶 `VALARM`，依「提前幾天提醒」設定；沒填時間的當成全天事件

> 學期起訖預設是 **2026-09-07 到 2027-01-08**，取自官方行事曆
> （9/7 預定舊生註冊、開學、正式上課；1/4–1/8 期末學習評量週，1/11 寒假開始）。
> 想改成別的日期，到「行事曆」或「重要日期」分頁都能改，改完可以一鍵改回官方值。

## 手機與電腦同步 🔄

預設**沒有**同步——資料只在各自的裝置上。想要兩台互通，得自己架一個很小的同步伺服器。

### 為什麼要自己架

這個 App 是公開的靜態網站，**任何人都能讀 JS 原始碼**。所以金鑰不能寫進程式裡，
不然等於公開。設計是：伺服器網址和密鑰由你在「設定」裡自己填，只存在裝置上，
不會進 bundle，也**不會進 JSON 備份**。

### 架設步驟（Cloudflare Workers，免費額度足夠）

```bash
cd worker
npx wrangler kv namespace create SYNC
```

把印出來的 namespace id 填進 `worker/wrangler.toml`，然後：

```bash
npx wrangler deploy
```

會得到一個像 `https://mcu-schedule-sync.你的帳號.workers.dev` 的網址。

### 兩台裝置設定

1. 第一台：設定 → 手機與電腦同步 → 填網址 → 按「產生新密鑰」→ 啟用同步
2. 按「顯示密鑰」，把那 32 個字抄到第二台
3. 第二台：填**一樣的**網址和密鑰 → 啟用同步

沒有帳號也沒有密碼——**那組密鑰就是憑證**。拿到密鑰的人就拿得到你的資料，不要外流。
Worker 只接受 `^[a-z0-9]{32}$` 格式的密鑰，猜中的機率可以忽略。

### 衝突怎麼處理

**不做無腦的後蓋前。** 推送時會帶上「我上次看到的版本」（`If-Match`），雲端如果已經被
另一台改過，伺服器回 409，App 會把兩邊的內容列出來讓你選：

```
這台：8 門課、3 筆待辦（2 筆未完成）、5 筆重要日期
雲端：8 門課、5 筆待辦（4 筆未完成）、5 筆重要日期
[用這台的，覆蓋雲端]  [用雲端的，覆蓋這台]
```

選之前先按「匯出 JSON 備份」，兩邊的資料就都不會真的不見。

其他行為：

- 改動後停 1.5 秒才推，不會每打一個字就打一次伺服器
- 切回這個分頁時會重新拉一次，所以另一台的改動看得到
- 全新的裝置（資料還是預設值）啟用同步時直接吃雲端的，不會跳沒必要的衝突
- 從雲端拉回來的資料一樣要過結構驗證和 schema migration 才會套用
- 連不上時如實顯示失敗，本機資料不動，網路好了按「立即同步」

> 這一項**違反了原本規格第 7 段的「不要加雲端同步」**，是後來明確決定要加的。
> 不想要的話，設定頁按「停用同步」就會回到純本機模式。

## 資料存在哪 💾

`localStorage`，key 是 `mcu-schedule.state.v1`。

- 每次寫入前都會先驗證結構，驗不過就**不覆蓋**舊資料，畫面上會顯示原因
- 讀取時如果資料壞掉，原始內容會搬到 `mcu-schedule.state.v1.corrupt` 留著備查，
  畫面用預設課表撐住而不是崩潰
- `version` 欄位用來做 schema migration，改結構時在 `src/lib/storage.ts` 的
  `migrations` 補一個 `N -> N+1` 的函式，舊資料就會自動升級。
  目前是 **v3**：
  - v1 -> v2 加了 `schoolEvents`，舊資料自動補成空陣列
  - v2 -> v3 把還停在暫定值的學期起訖換成官方日期；**你自己改過的不會被蓋掉**

**清除瀏覽器資料會把東西清光。** 換手機或重灌前，設定頁「匯出 JSON 備份」存一份。

## 專案結構

```
src/
  types.ts              資料型別
  constants.ts          節次時間、顯示順序、色盤、學期暫定值
  seed.ts               種子資料（真實課表）
  state.ts              useAppState：狀態與所有異動動作
  useReminders.ts       開著時的通知排程
  useTheme.ts           淺色／深色／跟隨系統
  sw.ts                 service worker（precache、字體快取、通知點擊）
  lib/
    dates.ts            台北時區的今天、倒數天數、節次換算
    schedule.ts         課表版面計算、課程配色
    schoolCalendar.ts   重要日期的區間、進行中判斷、近期篩選
    conflicts.ts        衝堂偵測
    ics.ts              .ics 產生器
    storage.ts          localStorage 讀寫、migration、JSON 備份
    validate.ts         結構驗證
    notifications.ts    通知能力偵測與當日提醒挑選
  data/
    academicCalendar.ts 官方行事曆轉出的靜態資料（不要手改）
  useSync.ts            同步的狀態機：拉、推、衝突處理
  lib/sync.ts           同步的 HTTP 層與樂觀鎖
worker/                 同步後端（Cloudflare Worker + KV）
  components/           畫面
```

## 沒有做的事

照規格刻意不做：登入、帳號、AI 功能、UI 元件庫、後端推播。

（**雲端同步**原本也在不做的清單裡，後來改成要做，見上面那一節。即使如此仍然沒有
帳號和密碼——憑證就是你自己產生的那組密鑰。）

另外**停課／補課／調整上課日**沒有做成課表層級的例外。課表本身維持固定週期；
遇到補課或停課，請到「重要日期」登記一筆，首頁就會提醒你，匯出的行事曆裡也會有。
但**課表格子本身不會因此改變**，這點要自己留意。
